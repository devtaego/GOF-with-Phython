Builder Pattern (빌더 패턴)
1. 빌더 패턴이란?
빌더 패턴(Builder Pattern)은 복잡한 객체를 생성하는 과정을 단계별로 분리하는 생성 디자인 패턴이다.

생성자의 매개변수가 많거나 선택적인 값이 많을 때, 생성자 하나에 모든 값을 넣는 대신 메서드를 통해 필요한 값을 하나씩 설정한 뒤 최종 객체를 생성한다.

핵심 구조
Builder
  ↓
필요한 값들을 단계적으로 설정
  ↓
build()
  ↓
최종 객체 생성
2. 왜 사용하는가?
예를 들어 회원 객체를 생성한다고 하자.

user = User(
    "재혁",
    31,
    "example@test.com",
    "010-1234-5678",
    "서울",
    True
)
매개변수가 많아지면 어떤 값이 어떤 의미인지 알아보기 어렵다.

특히 선택적인 값이 많아지면 다음과 같은 문제가 생긴다.

생성자 매개변수 순서를 기억해야 한다.

선택적인 값 때문에 None이 많아진다.

객체 생성 코드의 가독성이 떨어진다.

생성자를 여러 개 만들어야 할 수 있다.

빌더 패턴을 사용하면 다음처럼 작성할 수 있다.

user = (
    UserBuilder()
    .set_name("재혁")
    .set_age(31)
    .set_email("example@test.com")
    .set_address("서울")
    .build()
)
각 값이 무엇을 의미하는지 코드만 봐도 알기 쉽다.

3. 구성 요소
일반적인 빌더 패턴은 다음과 같이 구성된다.

Product
최종적으로 만들어지는 객체이다.

User
Builder
Product를 만들기 위한 생성 과정을 정의한다.

UserBuilder
build()
설정된 값을 이용하여 최종 Product를 생성한다.

UserBuilder.build()
    ↓
User 객체
4. Python 구현
아래 예제에서는 User 객체를 UserBuilder를 이용해 생성한다.

기본 코드
class User:
    def __init__(self, name, age, email=None, phone=None, address=None):
        self.name = name
        self.age = age
        self.email = email
        self.phone = phone
        self.address = address


class UserBuilder:
    def __init__(self):
        self.name = None
        self.age = None
        self.email = None
        self.phone = None
        self.address = None

    def set_name(self, name):
        self.name = name
        return self

    def set_age(self, age):
        self.age = age
        return self

    def set_email(self, email):
        self.email = email
        return self

    def set_phone(self, phone):
        self.phone = phone
        return self

    def set_address(self, address):
        self.address = address
        return self

    def build(self):
        if self.name is None:
            raise ValueError("name은 필수입니다.")

        if self.age is None:
            raise ValueError("age는 필수입니다.")

        return User(
            name=self.name,
            age=self.age,
            email=self.email,
            phone=self.phone,
            address=self.address
        )
사용할 때는 다음과 같다.

user = (
    UserBuilder()
    .set_name("재혁")
    .set_age(31)
    .set_email("example@test.com")
    .set_address("서울")
    .build()
)

print(user.name)
print(user.age)
print(user.email)
print(user.address)
5. 핵심은 메서드 체이닝
빌더 패턴에서 자주 사용하는 방식이 **메서드 체이닝(Method Chaining)**이다.

각 설정 메서드에서 self를 반환한다.

def set_name(self, name):
    self.name = name
    return self
그러면 다음처럼 연결할 수 있다.

UserBuilder() \
    .set_name("재혁") \
    .set_age(31) \
    .set_email("example@test.com") \
    .build()
각 메서드가 같은 Builder 객체를 반환하기 때문에 연속해서 호출할 수 있다.

6. 일반 생성자와 비교
생성자를 직접 사용하는 경우
user = User(
    "재혁",
    31,
    "example@test.com",
    None,
    "서울"
)
매개변수의 순서를 알아야 한다.

Builder를 사용하는 경우
user = (
    UserBuilder()
    .set_name("재혁")
    .set_age(31)
    .set_email("example@test.com")
    .set_address("서울")
    .build()
)
각 값의 의미가 코드에 드러난다.

7. 장점
가독성
객체 생성 과정이 명확하다.

UserBuilder() \
    .set_name("재혁") \
    .set_age(31) \
    .set_email("example@test.com") \
    .build()
선택적 값 처리
필요한 값만 설정할 수 있다.

user = (
    UserBuilder()
    .set_name("재혁")
    .set_age(31)
    .build()
)
email, phone, address는 설정하지 않아도 된다.

생성 로직 분리
객체 자체의 데이터 구조와 객체를 생성하는 과정을 분리할 수 있다.

8. 단점
코드가 많아진다
단순한 객체까지 Builder를 사용하면 오히려 코드가 복잡해질 수 있다.

User("재혁", 31)
정도로 충분한 객체라면 굳이 Builder를 만들 필요가 없다.

Builder 자체를 관리해야 한다
Product뿐만 아니라 Builder 클래스도 추가로 만들어야 한다.

따라서 생성 과정이 복잡하거나 선택적 속성이 많은 경우에 사용하는 것이 적절하다.

9. 언제 사용하는가?
다음 상황에서 Builder 패턴을 고려할 수 있다.

생성자 매개변수가 많다.

선택적인 속성이 많다.

같은 객체를 여러 가지 설정으로 생성해야 한다.

객체 생성 과정을 단계적으로 표현하고 싶다.

생성자의 가독성이 떨어진다.

반대로 생성해야 하는 값이 1~3개 정도이고 구조가 단순하다면 일반 생성자가 더 적절할 수 있다.

10. Java와의 연결
Java에서는 Builder 패턴을 매우 자주 볼 수 있다.

대표적으로 Lombok의 @Builder가 있다.

@Builder
public class User {
    private String name;
    private int age;
    private String email;
    private String phone;
}
그러면 다음처럼 객체를 생성할 수 있다.

User user = User.builder()
        .name("재혁")
        .age(31)
        .email("example@test.com")
        .build();
Python 예제와 구조가 거의 같다.

Python                         Java

UserBuilder()                  User.builder()
    .set_name(...)                 .name(...)
    .set_age(...)                  .age(...)
    .set_email(...)                .email(...)
    .build()                       .build()
11. 면접용 한 줄 정리
빌더 패턴은 복잡한 객체의 생성 과정을 단계별로 분리하여, 객체를 가독성 있고 유연하게 생성할 수 있도록 하는 생성 패턴이다.

기억할 키워드
Builder Pattern
    ↓
복잡한 객체 생성
    ↓
단계별 설정
    ↓
메서드 체이닝
    ↓
build()
    ↓
최종 객체
