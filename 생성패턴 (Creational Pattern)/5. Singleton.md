Singleton Pattern
1. 싱글톤 패턴이란?
싱글톤(Singleton) 패턴은 특정 클래스의 인스턴스를 하나만 생성하고, 어디서든 해당 인스턴스에 접근할 수 있도록 하는 생성 패턴이다.

"이 객체는 프로그램 전체에서 하나만 존재하게 하자."

라는 목적을 가진다.

2. 기본 구조
Singleton
 ├── private static instance
 ├── private constructor
 └── public static getInstance()
핵심 요소는 3가지이다.

생성자를 private으로 만든다.

클래스 내부에서 자신의 인스턴스를 관리한다.

외부에서는 getInstance()를 통해 인스턴스를 얻는다.

3. 기본 구현
public class Singleton {

    private static Singleton instance;

    private Singleton() {
    }

    public static Singleton getInstance() {

        if (instance == null) {
            instance = new Singleton();
        }

        return instance;
    }
}
사용:

Singleton s1 = Singleton.getInstance();
Singleton s2 = Singleton.getInstance();

System.out.println(s1 == s2); // true
getInstance()가 호출될 때마다 새로운 객체를 생성하는 것이 아니라 최초에 생성된 객체를 계속 반환한다.

4. 왜 생성자를 private으로 만드는가?
외부에서 직접 객체를 생성하는 것을 막기 위해서이다.

Singleton singleton = new Singleton();
위 코드는 생성자가 private이므로 사용할 수 없다.

객체 생성은 반드시 다음과 같이 이루어진다.

Singleton.getInstance();
5. 장점
5.1 인스턴스 하나만 사용
동일한 객체를 여러 곳에서 공유할 수 있다.

Singleton s1 = Singleton.getInstance();
Singleton s2 = Singleton.getInstance();

System.out.println(s1 == s2); // true
5.2 메모리 절약
동일한 객체를 여러 개 생성할 필요가 없는 경우 하나의 객체만 유지할 수 있다.

5.3 전역적인 접근
프로그램 어디에서든 동일한 인스턴스에 접근할 수 있다.

6. 단점
6.1 전역 상태
여러 곳에서 동일한 객체를 사용하기 때문에 객체의 상태가 변경되면 다른 코드에도 영향을 줄 수 있다.

Singleton.getInstance().setValue(10);
다른 곳에서도 동일한 객체를 사용하기 때문에 변경된 상태를 공유하게 된다.

6.2 테스트가 어려움
싱글톤 객체가 상태를 가지고 있다면 테스트 간에 상태가 공유될 수 있다.

테스트 A
   ↓
Singleton 상태 변경
   ↓
테스트 B
   ↓
변경된 상태를 그대로 사용
6.3 결합도 증가
여러 클래스가 싱글톤을 직접 호출하면 특정 구현에 강하게 의존하게 될 수 있다.

Singleton.getInstance();
이 코드가 프로그램 곳곳에 존재하면 싱글톤 구현을 변경하기 어려워질 수 있다.

7. Thread-Safe 문제
다음과 같은 기본 구현은 멀티스레드 환경에서 문제가 발생할 수 있다.

public static Singleton getInstance() {

    if (instance == null) {
        instance = new Singleton();
    }

    return instance;
}
두 개의 스레드가 동시에 접근하면 다음과 같은 상황이 발생할 수 있다.

Thread A                    Thread B

instance == null            instance == null
       ↓                           ↓
new Singleton()             new Singleton()
       ↓                           ↓
서로 다른 객체가 생성될 가능성
따라서 멀티스레드 환경에서는 별도의 동기화 방법을 고려해야 한다.

8. synchronized 방식
public class Singleton {

    private static Singleton instance;

    private Singleton() {
    }

    public static synchronized Singleton getInstance() {

        if (instance == null) {
            instance = new Singleton();
        }

        return instance;
    }
}
synchronized를 사용하면 한 번에 하나의 스레드만 getInstance()를 실행할 수 있다.

단점
getInstance()를 호출할 때마다 동기화 처리가 발생하기 때문에 성능상 부담이 생길 수 있다.

9. Eager Initialization
객체를 클래스가 로딩될 때 미리 생성하는 방법이다.

public class Singleton {

    private static final Singleton INSTANCE = new Singleton();

    private Singleton() {
    }

    public static Singleton getInstance() {
        return INSTANCE;
    }
}
장점
구현이 간단하다.

Thread-Safe하다.

단점
실제로 사용하지 않아도 객체가 생성된다.

객체 생성 비용이 큰 경우 비효율적일 수 있다.

10. Static Holder 방식
Java에서 많이 사용되는 Thread-Safe 싱글톤 구현 방법이다.

public class Singleton {

    private Singleton() {
    }

    private static class SingletonHolder {
        private static final Singleton INSTANCE = new Singleton();
    }

    public static Singleton getInstance() {
        return SingletonHolder.INSTANCE;
    }
}
SingletonHolder가 실제로 사용되는 시점에 초기화되므로 필요한 시점에 객체를 생성하면서 Thread-Safe를 보장할 수 있다.

11. Enum Singleton
Java에서는 Enum을 이용해서 싱글톤을 구현할 수도 있다.

public enum Singleton {

    INSTANCE;

    public void execute() {
        System.out.println("Singleton");
    }
}
사용:

Singleton.INSTANCE.execute();
Enum 방식은 Java의 Enum 특성상 인스턴스가 하나만 생성되는 것을 보장한다.

12. Spring과 Singleton
Spring에서는 기본적으로 Bean을 Singleton Scope로 관리한다.

@Service
public class UserService {

}
Spring Container가 해당 Bean을 하나 생성하고 필요한 곳에 동일한 객체를 주입한다.

Spring Container
       │
       ▼
  UserService
       │
   하나의 객체
    ↙     ↘
Controller Service
따라서 Spring에서는 직접 getInstance()를 구현하기보다 Spring Container가 객체의 생성과 생명주기를 관리하도록 하는 것이 일반적이다.

13. Singleton Pattern vs Spring Singleton
구분	Singleton Pattern	Spring Singleton
객체 생성	직접 관리	Spring Container가 관리
접근 방법	getInstance()	DI
생성자	보통 private	일반적으로 public 또는 package 접근
객체 관리	개발자가 직접 구현	Spring Container
기본 목적	인스턴스 하나 보장	Bean을 하나의 인스턴스로 관리
14. 언제 사용하는가?
싱글톤은 프로그램 전체에서 하나만 존재해도 되는 객체에 사용할 수 있다.

설정 관리 객체

로깅 객체

캐시 관리자

데이터베이스 연결 관리자

스레드 풀

Spring Bean

단, 단순히 "하나만 필요하다"는 이유만으로 무조건 싱글톤을 사용하는 것은 좋지 않다.

전역 상태와 결합도 증가, 테스트 어려움 등의 문제가 발생할 수 있기 때문이다.

15. 핵심 정리
Singleton Pattern

목적
→ 클래스의 인스턴스를 하나만 생성

핵심
→ private 생성자
→ static 인스턴스
→ getInstance()

장점
→ 인스턴스 하나만 유지
→ 객체 공유
→ 불필요한 객체 생성 방지

단점
→ 전역 상태
→ 테스트 어려움
→ 결합도 증가 가능
→ 멀티스레드 고려 필요

Java 구현 방법
→ Lazy Initialization
→ synchronized
→ Eager Initialization
→ Static Holder
→ Enum

Spring
→ 기본 Bean Scope가 Singleton
→ Spring Container가 객체 생명주기를 관리
→ 직접 Singleton 패턴을 구현할 필요가 없는 경우가 많음
16. 면접 한 줄 답변
싱글톤 패턴은 클래스의 인스턴스를 하나만 생성하고 이를 공유하도록 하는 생성 패턴입니다. 객체의 중복 생성을 방지할 수 있지만 전역 상태와 결합도 증가 등의 단점이 있어 사용 목적을 고려해야 합니다. Spring에서는 직접 싱글톤을 구현하기보다 Spring Container가 Singleton Scope의 Bean을 관리합니다.
