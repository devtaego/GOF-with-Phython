 Prototype 패턴 정리

# Prototype 패턴

 ## 1\. 개념

 **Prototype(프로토타입) 패턴**은 기존 객체를 복제(Clone)하여 새로운 객체를 생성하는 **생성(Creational) 디자인 패턴**이다.

 객체를 새로 생성할 때 복잡한 초기화 과정을 반복하는 대신, 이미 만들어진 객체를 복제하여 사용할 수 있다.

 ### 핵심 아이디어

 > **"기존 객체를 복사해서 새로운 객체를 만든다."**

 일반적인 객체 생성:

```
new User(...);
```

 Prototype 패턴:

```
User clonedUser = user.clone();
```

---

 ## 2\. 사용하는 이유

 객체 생성 과정이 다음과 같이 복잡한 경우 유용하다.

 - 객체 생성 과정이 복잡한 경우
- 객체 초기화에 많은 비용이 드는 경우
- 비슷한 객체를 여러 개 생성해야 하는 경우
- 생성할 객체의 구체적인 클래스를 코드에서 직접 지정하고 싶지 않은 경우
- 기존 객체의 상태를 기반으로 새로운 객체를 만들고 싶은 경우

---

 ## 3\. 구조

```
        ┌──────────────────┐
        │    Prototype     │
        │                  │
        │ + clone()        │
        └────────┬─────────┘
                 △
                 │
        ┌────────┴─────────┐
        │ ConcretePrototype│
        │                  │
        │ + clone()        │
        └──────────────────┘
                 │
                 │ 복제
                 ▼
        ┌──────────────────┐
        │   새로운 객체    │
        └──────────────────┘
```

 ### 구성 요소

 #### Prototype

 객체를 복제하기 위한 인터페이스 또는 추상 클래스.

```
interface Prototype {
    Prototype clone();
}
```

 #### ConcretePrototype

 실제로 복제되는 객체.

```
class User implements Prototype {

    private String name;

    public User(String name) {
        this.name = name;
    }

    @Override
    public User clone() {
        return new User(this.name);
    }
}
```

 #### Client

 Prototype의 `clone()`을 호출하여 객체를 생성한다.

```
User user1 = new User("Kim");
User user2 = user1.clone();
```

 # 4\. Java 예제

 ## 기본적인 구현

```
class User implements Cloneable {

    private String name;
    private int age;

    public User(String name, int age) {
        this.name = name;
        this.age = age;
    }

    @Override
    public User clone() {
        try {
            return (User) super.clone();
        } catch (CloneNotSupportedException e) {
            throw new AssertionError();
        }
    }
}
```

 사용:

```
User user1 = new User("Kim", 20);

User user2 = user1.clone();

System.out.println(user1 == user2); // false
```

 `user1`과 `user2`는 서로 다른 객체지만 같은 상태를 가지고 있다.

```
user1
 ├─ name = "Kim"
 └─ age = 20

        clone()

user2
 ├─ name = "Kim"
 └─ age = 20
```

 # 5\. 얕은 복사와 깊은 복사

 Prototype 패턴에서 가장 중요한 개념 중 하나이다.

 ## 얕은 복사(Shallow Copy)

 객체 자체는 복사하지만 내부에서 참조하고 있는 객체는 공유한다.

```
원본 객체
   │
   ├── name
   │
   └── Address ─────┐
                    │
복제 객체           │
   │                │
   ├── name         │
   │                │
   └── Address ─────┘
```

 즉,

```
user1.getAddress() == user2.getAddress()
```

 가 `true`가 될 수 있다.

---

 ## 깊은 복사(Deep Copy)

 객체뿐만 아니라 내부에서 참조하는 객체까지 새롭게 복사한다.

```
원본 객체
   │
   └── Address A

복제 객체
   │
   └── Address B
```

 서로 다른 객체를 참조한다.

```
user1.getAddress() != user2.getAddress()
```

---

 # 6\. 깊은 복사 예제

```
class Address {

    private String city;

    public Address(String city) {
        this.city = city;
    }

    public Address(Address address) {
        this.city = address.city;
    }
}
```

```
class User {

    private String name;
    private Address address;

    public User(String name, Address address) {
        this.name = name;
        this.address = address;
    }

    public User clone() {
        return new User(
            this.name,
            new Address(this.address)
        );
    }
}
```

 이 경우 `User`뿐만 아니라 `Address`도 새롭게 생성된다.

 # 7\. Prototype 패턴의 장점

 ## ① 객체 생성 비용 감소

 복잡한 객체를 처음부터 생성하는 대신 기존 객체를 복제할 수 있다.

```
복잡한 생성 과정
      ↓
   Prototype
      ↓
     clone()
      ↓
 새로운 객체
```

---

 ## ② 객체 생성 과정의 캡슐화

 객체를 생성하기 위해 필요한 복잡한 과정을 Client가 알 필요가 없다.

```
User user = prototype.clone();
```

 Client는 내부 생성 과정을 몰라도 된다.

---

 ## ③ 다양한 객체를 동적으로 생성 가능

 실제 객체의 구체적인 클래스를 직접 알지 않아도 Prototype을 통해 객체를 생성할 수 있다.

---

 # 8\. 단점

 ## ① 복사 과정이 복잡할 수 있음

 객체 내부에 다른 객체가 많이 포함되어 있다면 깊은 복사를 구현하기 어려워질 수 있다.

```
User
 └─ Address
     └─ Company
         └─ Department
             └─ ...
```

 어디까지 복사해야 하는지 결정해야 한다.

---

 ## ② 순환 참조 문제

 객체가 서로를 참조하는 구조에서는 깊은 복사가 복잡해질 수 있다.

```
A → B
↑   ↓
└───┘
```

---

 ## ③ 얕은 복사로 인한 문제

 참조 객체를 공유하면 한 객체를 수정했을 때 다른 객체에도 영향을 줄 수 있다.

---

 # 9\. Prototype과 일반적인 객체 생성 비교

 ### 일반적인 생성

```
User user1 = new User(
    "Kim",
    20,
    new Address("Seoul")
);
```

 객체 생성에 필요한 정보를 직접 전달해야 한다.

 ### Prototype

```
User user2 = user1.clone();
```

 기존 객체의 상태를 기반으로 새로운 객체를 만든다.

---

 # 10\. Prototype과 Factory 비교

 | 구분 | Prototype | Factory |
| --- | --- | --- |
| 생성 방법 | 기존 객체 복제 | 새 객체 생성 |
| 핵심 | `clone()` | 객체 생성 로직 |
| 기존 상태 | 유지하여 복사 가능 | 일반적으로 새롭게 설정 |
| 복잡한 객체 | 복제에 유리 | 생성 로직이 복잡해질 수 있음 |
| 주요 목적 | 객체 복사 | 객체 생성 캡슐화 |

쉽게 말하면:

```
Factory
"새로 만들어줘"

Prototype
"이거랑 똑같이 하나 만들어줘"
```

 # 11\. 실무에서의 활용 예

 Prototype 패턴은 다음과 같은 상황에서 활용할 수 있다.

 ### 게임

```
Monster Prototype
       │
       ├── clone() → Monster 1
       ├── clone() → Monster 2
       └── clone() → Monster 3
```

 기본 몬스터의 설정을 복제하여 여러 몬스터를 생성할 수 있다.

 ### 문서 시스템

```
Document Prototype
       │
       ├── clone() → Document A
       ├── clone() → Document B
       └── clone() → Document C
```

 기본 문서 양식을 복제하여 새로운 문서를 만들 수 있다.

 ### 설정 객체

 기본 설정을 복제하고 일부 값만 변경하여 여러 설정 객체를 만들 수 있다.

 # 12\. 핵심 코드

 Prototype 패턴의 핵심은 다음과 같다.

```
interface Prototype {
    Prototype clone();
}
```

```
class ConcretePrototype implements Prototype {

    private String value;

    public ConcretePrototype(String value) {
        this.value = value;
    }

    @Override
    public ConcretePrototype clone() {
        return new ConcretePrototype(this.value);
    }
}
```

 사용:

```
ConcretePrototype original =
    new ConcretePrototype("Hello");

ConcretePrototype copy =
    original.clone();
```

---

 # 13\. 핵심 정리

 Prototype 패턴은 **기존 객체를 복제하여 새로운 객체를 생성하는 생성 패턴**이다.

 ### 핵심 키워드

```
Prototype
    ↓
기존 객체
    ↓
clone()
    ↓
새로운 객체
```

 ### 기억할 것

 - 생성(Creational) 디자인 패턴
- 기존 객체를 복제해서 새로운 객체 생성
- 객체 생성 과정이 복잡할 때 유용
- `clone()`이 대표적인 구현 방법
- 얕은 복사와 깊은 복사를 구분해야 함
- 내부 참조 객체가 있다면 복사 범위를 주의해야 함

 > **Prototype = "기존 객체를 복사해서 새로운 객체를 만든다."**
