# Factory Method Pattern (팩토리 메서드 패턴)

## 1. 정의

**객체를 생성하는 인터페이스를 정의하고, 어떤 객체를 생성할지는 서브클래스가 결정하도록 하는 생성 패턴**

즉, 객체를 직접 `new`로 생성하지 않고 **객체 생성을 별도의 메서드에 맡기는 패턴**이다.

> 핵심: **"무엇을 만들지는 자식 클래스가 결정한다."**

---

## 2. 왜 사용하는가?

일반적으로 객체를 직접 생성하면 다음과 같은 문제가 생길 수 있다.

```java
Payment payment = new CardPayment();
```

나중에 결제 방식이 추가되면 기존 코드의 `new` 부분을 계속 수정해야 한다.

```java
Payment payment = new CardPayment();
// → KakaoPayment
// → NaverPayment
// → BankTransferPayment
```

Factory Method를 사용하면 **객체 생성 부분을 분리**할 수 있다.

---

## 3. 구조

Factory Method에는 일반적으로 다음 요소가 존재한다.

```text
Product
  ↑
ConcreteProduct

Creator
  ↑
ConcreteCreator
```

### 역할

| 구성 요소           | 역할                          |
| --------------- | --------------------------- |
| Product         | 생성할 객체의 인터페이스               |
| ConcreteProduct | 실제 생성되는 객체                  |
| Creator         | Factory Method를 선언          |
| ConcreteCreator | 어떤 ConcreteProduct를 생성할지 결정 |

---

## 4. 기본 예제

### Product

```java
public interface Payment {
    void pay();
}
```

---

### ConcreteProduct

```java
public class CardPayment implements Payment {

    @Override
    public void pay() {
        System.out.println("카드 결제");
    }
}
```

```java
public class KakaoPayment implements Payment {

    @Override
    public void pay() {
        System.out.println("카카오페이 결제");
    }
}
```

---

### Creator

```java
public abstract class PaymentFactory {

    public abstract Payment createPayment();

    public void processPayment() {
        Payment payment = createPayment();
        payment.pay();
    }
}
```

`createPayment()`가 **Factory Method**이다.

---

### ConcreteCreator

```java
public class CardPaymentFactory extends PaymentFactory {

    @Override
    public Payment createPayment() {
        return new CardPayment();
    }
}
```

```java
public class KakaoPaymentFactory extends PaymentFactory {

    @Override
    public Payment createPayment() {
        return new KakaoPayment();
    }
}
```

---

### 사용

```java
public class Main {

    public static void main(String[] args) {

        PaymentFactory factory;

        factory = new CardPaymentFactory();
        factory.processPayment();

        factory = new KakaoPaymentFactory();
        factory.processPayment();
    }
}
```

실행 결과:

```text
카드 결제
카카오페이 결제
```

# 5. 핵심 구조 이해

다음 부분이 가장 중요하다.

```java
public abstract class PaymentFactory {

    public abstract Payment createPayment();

    public void processPayment() {
        Payment payment = createPayment();
        payment.pay();
    }
}
```

부모 클래스는

```java
Payment payment = createPayment();
```

까지만 알고 있다.

**실제로 어떤 Payment를 만들지는 자식 클래스가 결정한다.**

```java
CardPaymentFactory
        ↓
new CardPayment()

KakaoPaymentFactory
        ↓
new KakaoPayment()
```

즉,

```text
Creator
   │
   └── createPayment()
          │
          ├── CardPaymentFactory
          │       └── CardPayment
          │
          └── KakaoPaymentFactory
                  └── KakaoPayment
```

# 6. 일반적인 객체 생성과 비교

## Factory Method를 사용하지 않는 경우

```java
public void process(String type) {

    Payment payment;

    if (type.equals("card")) {
        payment = new CardPayment();
    } else if (type.equals("kakao")) {
        payment = new KakaoPayment();
    }

    payment.pay();
}
```

결제 방법이 추가될수록 `if-else`가 계속 증가한다.

---

## Factory Method 사용

```java
PaymentFactory factory;

if (type.equals("card")) {
    factory = new CardPaymentFactory();
} else {
    factory = new KakaoPaymentFactory();
}

factory.processPayment();
```

객체 생성 책임을 Factory 쪽으로 분리할 수 있다.

---

# 7. 장점

### ① 객체 생성과 사용을 분리

객체를 사용하는 코드가 구체적인 구현 클래스에 직접 의존하지 않도록 만들 수 있다.

```java
Payment payment = createPayment();
```

사용하는 쪽에서는 `CardPayment`인지 `KakaoPayment`인지 몰라도 된다.

---

### ② 확장에 유리

새로운 결제 방식이 추가되더라도 기존 Product 구조를 유지하면서 새로운 Factory를 추가할 수 있다.

```text
Payment
 ├── CardPayment
 ├── KakaoPayment
 └── NaverPayment

PaymentFactory
 ├── CardPaymentFactory
 ├── KakaoPaymentFactory
 └── NaverPaymentFactory
```

---

### ③ 객체 생성 로직을 한 곳에 모을 수 있음

복잡한 객체 생성 과정을 Factory에서 관리할 수 있다.

---

# 8. 단점

### ① 클래스가 많아질 수 있음

제품 하나마다 Factory가 필요하다면 클래스가 증가한다.

```text
CardPayment
CardPaymentFactory

KakaoPayment
KakaoPaymentFactory

NaverPayment
NaverPaymentFactory
```

---

### ② 구조가 복잡해질 수 있음

단순히 객체 하나를 생성하는 상황에서 Factory Method를 사용하면 오히려 코드가 복잡해질 수 있다.

---

# 9. 언제 사용하는가?

다음과 같은 상황에서 고려할 수 있다.

* 어떤 객체를 생성할지 실행 시점에 결정해야 할 때
* 객체 생성 로직과 사용 로직을 분리하고 싶을 때
* 새로운 객체 종류가 계속 추가될 가능성이 있을 때
* 부모 클래스는 객체의 사용 방법만 알고 있으면 될 때
* `new`가 여러 곳에 흩어지는 것을 방지하고 싶을 때

# 10. Factory Method vs 단순 Factory

둘은 비슷해 보이지만 구조가 다르다.

## Simple Factory

```java
public class PaymentFactory {

    public static Payment create(String type) {

        if (type.equals("card")) {
            return new CardPayment();
        }

        if (type.equals("kakao")) {
            return new KakaoPayment();
        }

        throw new IllegalArgumentException();
    }
}
```

하나의 Factory가 조건에 따라 객체를 생성한다.

```text
PaymentFactory
 ├── card → CardPayment
 └── kakao → KakaoPayment
```

---

## Factory Method

```text
PaymentFactory
      ↑
      │
 ┌────┴──────────────┐
 │                   │
CardFactory      KakaoFactory
 │                   │
 ↓                   ↓
CardPayment      KakaoPayment
```

**객체 생성 방법 자체를 서브클래스에게 맡긴다.**

---

# 11. Factory Method 핵심 코드

시험이나 면접에서는 다음 구조를 기억하면 된다.

```java
abstract class Creator {

    // Factory Method
    public abstract Product createProduct();

    public void operation() {
        Product product = createProduct();
        product.use();
    }
}
```

```java
class ConcreteCreator extends Creator {

    @Override
    public Product createProduct() {
        return new ConcreteProduct();
    }
}
```

핵심은:

```java
createProduct()
```

를 **자식 클래스에서 구현한다는 것**이다.

---

# 12. 한 줄 암기

> **Factory Method = 객체 생성 메서드를 정의하고, 실제 어떤 객체를 만들지는 서브클래스가 결정하는 패턴**

### 핵심 키워드

```text
객체 생성 캡슐화
        ↓
Factory Method
        ↓
서브클래스가 구체적인 객체 결정
```

# 13. 면접 답변

**Q. 팩토리 메서드 패턴이 무엇인가요?**

> 객체를 생성하는 인터페이스를 정의하고, 실제 어떤 객체를 생성할지는 서브클래스가 결정하도록 하는 생성 패턴입니다. 객체 생성과 사용을 분리할 수 있기 때문에 새로운 객체 타입이 추가될 때 기존 코드를 변경하는 것을 줄일 수 있습니다.

**Q. 단순 팩토리와 차이점은 무엇인가요?**

> 단순 팩토리는 하나의 Factory에서 조건문 등을 통해 객체를 생성하는 방식이고, 팩토리 메서드는 객체 생성 메서드를 정의한 뒤 이를 서브클래스에서 구현하도록 하는 방식입니다.

**Q. 가장 중요한 특징은?**

> **객체 생성의 책임을 서브클래스로 넘긴다는 것**입니다.
